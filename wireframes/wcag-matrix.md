# WCAG 2.1 AA Compliance Mastrix

| Criteria ID and Name | Target Interface Component | Technical Implementation Detail | Verification Strategy |
| :--- | :--- | :--- | :--- |
| **1.3.1 Info and Relationships (A)** | `BookingForm.jsx` | Uses React `useId()` hooks to programmatically associate `<label>` elements and `<p>` error messages to their corresponding `<input>` fields via `aria-describedby` | Inspect DOM to confirm label `for` matches input `id`. Test with screen reader to ensure label and error hints are read on focus |
| **1.4.3 Contrast (Minimum) (AA)** | `Home.jsx`, `ResourceDirectory.jsx` | Text utilities use explicit dark gray styling (`text-gray-900`) on white containers (`bg-white`) and white text on dark blue (`bg-blue-950`). Forced `color-scheme: light` in `index.css` | Run Chrome Lighthouse accessibility audit and manual color picker checks to verify contrast ratios exceed 4.5:1 |
| **2.1.1 Keyboard** (Level A) | `App.jsx` Navigation, `Modal.jsx` | Built with standard native HTML elements (`<button>`, `<input>`). No custom non-interactive elements are used without key handlers | Navigate through all views using only `Tab`, `Shift+Tab`, `Space`, and `Enter` without using a mouse |
| **2.1.1 Focus Order (A)** | `Modal.jsx` | Focus moves automatically into the dialog container when opened using `ref.focus()`. Returns focus to the trigger button upon closing | Open the modal via keyboard, press `Tab` to confirm focus stays inside, and press `Escape` to ensure focus returns to the open button |
| **2.4.7 Focus Visible (AA)** | Interactive Buttons & Fields | Styled focus rings using `focus-visible:outline focus-visible:outline-2 focus-visible:outline-blue-700` across all buttons and form inputs | Tab through the entire app and visually verify that every focused element displays a high-contrast focus outline |
| **4.1.2 Name, Role, Value (A)** | `ResourceDirectory.jsx` | Controls use `aria-expanded` for collapsible filter panels, `aria-current="page"` for active navigation tabs and `aria-live="polite"` for dynamic list updates | Filter services while using a screen reader to verify that category changes announce dynamically without refreshing |
